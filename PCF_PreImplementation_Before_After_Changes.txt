Scope: make the original two-flow Home + ShelfWorkspace recipe consistent and

MAIN GAPS
- Local state survives a workspace switch and is lost on a narrow-layout tab switch.
- A command can disappear between updateView and the React effect that uses it.
- An overlay does not itself stop keyboard/microphone interaction.
- Sending without sources clears the draft before the host rejects it.
- Duplicate filenames resolve citations ambiguously; unresolved events can double.
- Quiz state carries between quizzes; final answer emits two last-event outputs.
- File reads can overlap, return null, exceed remaining slots, or continue after close.
- Add-source copy describes flagging that the code never enforces.
- File/text validation, extracted content, browser links and settings persistence
  must be completed in the flows rather than inferred from the workbook.
- Startup and the flow snapshot contract need matching host changes.
- The existing solution-build helper must isolate sibling manifests.

FLOW AND DATAVERSE CHANGES - REQUIRED MATCHING WORK
=================================================
There are no flow exports in this project. The BEFORE descriptions below refer
to the earlier implementation guide, not a deployed flow we have inspected.
Keep exactly two Power Apps-triggered flows; add Switch branches within them.

F1. COMPLETE THE FLOW RESPONSE CONTRACT VALIDATION
LOCATION: both flows, immediately before Compose_Response / Respond to PowerApp.
BEFORE: a Compose object is serialized and returned without a structural gate.
AFTER: add Parse JSON named Validate_Response, using the full success/error schema
defined below. Content = outputs('Compose_Response'). Respond with:
    string(body('Validate_Response'))
On validation failure use Catch to return ok:false with the current requestId;
never return a partial state with ok:true. Validate input branches too, using the
three source schemas and agent-reply schema from the earlier guide.

The response schema validates structure; add Conditions for cross-record rules:
  - Source/message/output IDs are unique and refer to actual records.
  - selectedSourceIds is a subset of nonflagged sources authorized to the caller.
  - Citation source IDs belong to the selected set; filename fallback is unique.
  - Citation indices are positive, unique within a message, and match the answer.
  - Workspace id is nonempty for state.view=workspace and empty for home.
  - viewerJson is blank or parses into a COMPLETE ViewerPayload, never a bare array.
  - SourceLimit is positive; maxInlineFileBytes is within configured policy.
  - Order messages by rcpg_sequence, not createdon or arbitrary API return order.

For viewerJson add a Switch on json(viewerJson).type and a validation condition:
  doc: data.id/title/group/kind must match a source the caller can access.
  slides: data.id/title and nonempty slides array; every slide has title and string[] bullets.
  quiz: data.id/title, 1..maxQuizQuestions questions, passMark 0..100; unique question
        ids; nonempty prompt; >=2 string options; integer answerIndex in range.
  text: data.id/title and sections array; each section has a string body.
  path: data.id/title/role/level and modules array; positive unique n; string title;
        sourceTitles string[]; done boolean. Load module state from rcpg_pathmodule.
Reject unknown viewer types. The small parseJson change is not a substitute for
this server validation. Catch malformed responses rather than normalizing them
silently to empty successful content.

F2. VALIDATE SOURCE CONTENT BEFORE MAKING IT USABLE
LOCATION: FLOW_VALIDATE > AddLinkRequested / AddTextRequested / AddFileRequested.
BEFORE: the guide leaves extractor/classifier/link infrastructure to configure.
AFTER: configure it explicitly before enabling file types in the UI:
  1. Recheck workspace authorization and remaining slots on the server.
  2. Enforce <=1.5 MiB/file, <=3 MiB total decoded bytes/request, <=50000 pasted
     text characters, supported extensions and matching content signatures.
     Match appsetting if it imposes LOWER limits. Client checks can be bypassed.
  3. Decode raw base64 with base64ToBinary, extract text for the real format.
     TXT/MD/CSV: decode the supported encoding. PDF/DOCX: configure an extractor;
     scanned documents require OCR. Reject unreadable/encrypted/unsupported data.
  4. URL: resolve/fetch with an approved service, validate redirects, destination
     restrictions, authentication, size, MIME/content; extract readable text.
  5. Classify against the configured domain and validation policy. Treat source
     text as data; do not let instructions inside it override validation.
  6. Save rcpg_file and source metadata only as part of an accepted source.
     Store pasted text as a UTF-8 .txt, kind=file. Preserve all original content.
  7. Persist extracted text or an access-controlled retrieval reference. The
     workbook has no extracted-text or indexing-status field. Two valid options:
       A. Keep the existing schema and re-extract on chat requests within the
          time budget; explicitly implement extraction in FLOW_CHAT too.
       B. Recommended for repeated chat: ADD rcpg_source.rcpg_contenttext,
          Multiple Lines of Text, with a configured max length. Save bounded
          extracted text there; reject oversize input or use chunk storage and
          retrieval infrastructure instead of silently truncating it.
     rcpg_contenttext is a NEW proposed column, not present in the workbook.
     Never store a full document in rcpg_summary just to avoid defining storage.
  8. Publish an authenticated URL the browser can actually open. If unavailable,
     return empty url/downloadUrl; the PCF disables download and shows summary.
  9. Return accepted/rejected/failed per item and a complete usable-source snapshot.
     Do not insert rejected items as selectable knowledge. Clean up temporary rows
     on failed uploads. Only after extraction/validation succeeds is a row usable.

Persisting a file to Dataverse is NOT equivalent to adding it to Copilot knowledge.
FLOW_CHAT must fetch authorized selected content (or an agent retrieval tool must
apply the workspace/source filter). A list of GUIDs in a prompt is insufficient.

F3. PREVENT OLD CONVERSATION CONTENT FROM BYPASSING SOURCE SELECTION
LOCATION: FLOW_CHAT > AskQuestion > before Execute_Agent_and_wait.
BEFORE: reuse request.conversationId without a persisted source-set comparison.
AFTER: use the server's saved conversation id and compare its source context.
For a simple version with no new schema, start a fresh agent conversation on EVERY
question and supply only the current selected passages plus sanitized permitted
context. This sacrifices Copilot-side conversational memory, but avoids claiming
source isolation while old source text remains in that memory.
For conversation reuse, ADD these proposed fields on rcpg_workspace:
  rcpg_conversationid       Text (current agent session)
  rcpg_conversationsources  Multiple Lines of Text (canonical selected-id JSON)
Canonicalize by sorting and de-duplicating the selected source GUIDs. Also reset
conversation when a source's content changes, the caller changes in a shared
workspace, or relevant access/strict-source policy changes. For shared workspaces,
use per-user conversation records instead of these workspace-wide columns.

Before execute: server context differs -> Conversation ID blank.
After execute: persist returned conversationId and the validated context. Keep
writing rcpg_chatmessage.rcpg_conversationid for historical message auditing.
Never use a caller-supplied conversation id without verifying its association.
Flow outputs state.conversationId from the saved current session.
Both alternatives require explicit grounding enforcement; a prompt instruction
alone cannot constrain an agent that is allowed to search unrelated knowledge.

F4. PERSIST WORKSPACE SETTINGS IF YOU WANT THEM TO SURVIVE REOPEN
LOCATION: Dataverse > rcpg_workspace; FLOW_CHAT > WorkspaceSettingsSaved/open/load.
BEFORE: answerStyle/citationMode/strictSources are session-only in the guide.
AFTER (recommended schema addition): add rcpg_settingsjson, Multiple Lines of Text.
On WorkspaceSettingsSaved validate the payload (it is NOT {values:...}), update

On load parse saved settings and merge validated defaults for missing properties.
Set settings.title/emoji from workspace columns; set passMark from server policy.
Do not save arbitrary client keys or client-supplied role/limit values as settings.
If you retain session-only behavior, no schema addition is necessary; clearly tell
users those three preferences reset when a workspace is reopened.

F5. SAVE AND GRADE THE NEW QUIZ COMPLETION PAYLOAD
LOCATION: FLOW_CHAT > QuizCompleted (replace the baseline summary-only handling).
BEFORE: trust reported total/correct, recompute score, ignore per-question answers.
AFTER: Parse completion JSON with required attemptId,quizId,answers,durationSeconds.
answers is [{questionId:string,selectedIndex:integer,answeredAt:ISO string}].
The PCF still sends summary fields for UI compatibility; do not trust them for grading.
Load the persisted quiz by quizId, verify access/workspace, then:
  - Each saved question id must occur exactly once in answers; reject extras.
  - Every selectedIndex is within that question's saved options array.
  - correct = count where selectedIndex equals the saved answerIndex.
  - total = saved question count; score = round(100 * correct / total).
  - passMark = saved quiz passMark; passed = score >= passMark.
  - Bound/check durationSeconds; do not treat a client clock as authoritative.
Create rcpg_quizattempt with the workbook's columns and authenticated systemuser.
Use attemptId as the primary key ONLY if it is a valid GUID and your Dataverse
create action/API allows setting rcpg_quizattemptid. Otherwise add a NEW Text column
rcpg_clientattemptid plus an active alternate key and use that for idempotency.
A conflicting attempt id belonging to another user/quiz must be denied, not reused.
If already saved for the same user/quiz, return the existing result, not a new row.
If rcpg_quizanswer is enabled, create detail rows linked to that saved attempt,
using server-computed correctness. Add a unique key on attempt + question id if
you need safe repeated writes; continue/repair incomplete child writes on retry.
Return the saved quiz viewer. Reopening a quiz starts a new attempt, by design.
This learning UI exposes correct answers in the client; it is not a secure exam.

F6. RETRY, CONCURRENCY, AND RESPONSE DEADLINES
LOCATION: both flow triggers and every mutation branch.
BEFORE: requestId is only echoed; app has no automatic retry and reloads after timeout.
AFTER: keep no-automatic-retry for the baseline. Disable long retries on agent/
OCR actions and test total response time below the documented synchronous window.
Serialize conflicting workspace writes for the initial small installation. Separate
flow concurrency=1 settings do NOT serialize one flow against the other; source
limit check + create needs a shared server lock/transaction if different users can
write the same workspace concurrently. Do not use Max(sequence)+1 concurrently.

For automatic retries, add a request ledger with a unique requestId and atomic
claim, saved owner/workspace/operation/status/result, and safe resume semantics.
A read-then-create without a unique key is not a lock. Reuse the ORIGINAL requestId
for a retry; the guide currently generates a new id for each explicit user request.
Adding a ledger alone cannot undo an external agent call that already completed.
If the real workload needs >120-second responses, add submit/status operations
and persistent job state to the SAME two flow connections, plus an app polling
timer. That is a separate asynchronous contract; do not simply increase .Run wait
or claim the synchronous formulas support arbitrarily long OCR/generation.

VERIFICATION REQUIRED BEFORE PUBLISHING
======================================
1. Build both required controls; Canvas App Checker must pass the revised formulas.
2. Cold start: initialization runs once after App.OnStart; failed init can Reload.
3. Open workspace A, type a draft, switch to B: no A draft/viewer/selection survives.
4. Narrow layout: changing chat/source tabs preserves draft and unfinished quiz;
   microphone stops while hidden; returning does not reapply an old draft command.
5. No selected sources: Enter, Send and follow-up do not clear/submit a question.
6. Double-click Send: one foreground AskQuestion. Failed flow restores draft and
   permits another send. Two sequential host updateView calls do not lose commands.
7. Two sources with identical names: citation sourceId wins; missing sourceId is
   unresolved unless exactly one filename match exists. Only one event is emitted.
8. Upload zero-byte, oversize, unsupported, unreadable, >3 MiB batch, or too many
   files: no invalid AddFileRequested is emitted. Cancel/unmount during a read
   cannot later attach files to a different workspace. Server repeats all checks.
9. Open quiz A then quiz B with the same question ids: B starts fresh. Complete B:
   exactly one QuizCompleted includes all answers and a stable attemptId. Server
   grades saved answers, saves one attempt and optional detail rows, handles replay.
10. Change selected content and ask again: previous source knowledge cannot leak
    through a reused Copilot conversation or unrestricted agent retrieval.
11. Malformed response/viewer payload, source-policy denial and connector timeout:
    show an error, preserve committed state, unlock the UI, and allow Reload.
12. Open/download files with a second authorized user, and deny another user's
    workspace/source/quiz/conversation ids sent directly to either flow.
